# Third-party components

This repository publishes source only. The portable-build inventory below describes separately assembled local builds; no binaries, game screenshots, user settings or private runtime artifacts are included here.

## UI development checks (not bundled runtime)

`axe-core` 4.10.3 is pinned as a development dependency for isolated renderer accessibility checks, under MPL-2.0 ([upstream](https://github.com/dequelabs/axe-core)). It does not run in the production renderer or add a UI library. A workspace with shared `node_modules` can use `npm run setup:ui-a11y`, which installs the fixed package with lifecycle scripts disabled under ignored `artifacts/ui-a11y-tools`; it never installs through the application's shared dependency junction. Reports record the engine version, violations and incomplete checks; automated scanning is not a full accessibility certification.

The portable Windows x64 build includes the following upstream runtime packages. MaaCore task resources receive a documented startup patch only in the built copy; its upstream ZIP and vendor remain unchanged, and `gamepilot-resource-patches.json` records that modification. `package-manifest.json` records the installed Electron/Maa versions and SHA-256 of every packaged file. The application version comes from the root `package.json`; the packager rejects a mismatched lockfile. The package also includes the exact committed GamePilot application source archive; upstream corresponding-source requirements remain separate.

The native libraries require the Microsoft Visual C++ v14 **x64** runtime on the target computer. PE import tables directly reference `MSVCP140.dll`, `MSVCP140_1.dll`, `VCRUNTIME140.dll`, `VCRUNTIME140_1.dll`, and `CONCRT140.dll`; these files are not included by the npm or Electron distributions. Use the [official Microsoft runtime download](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist) if needed. The portable folder therefore includes its application/npm dependencies but does not constitute a prerequisite-free Windows installation.

## Native library replacement and source

Maa is loaded dynamically by the separate execution process. Its npm packages and DLLs remain unpacked under `resources/app/node_modules/@maaxyz`, so an interface-compatible modified build can replace them while the application is closed. GamePilot imposes no restriction on modifying those library portions or reverse engineering to debug those modifications. Do not replace library files while the execution process is running.

Upstream source and build instructions are in [MaaFramework v5.13.0](https://github.com/MaaXYZ/MaaFramework/tree/v5.13.0), including its pinned submodules, and [MaaDeps v2.12.6](https://github.com/MaaXYZ/MaaDeps/tree/v2.12.6). This portable folder does not include a complete corresponding-source archive; an upstream URL is not described here as such an archive. The locally maintained application source remains in the development workspace and is not automatically shipped by this script.

## Scope of this packaging audit

The native npm distribution also includes OpenCV, DirectML, ViGEmClient, Maa's Android agent binaries, and a demo plugin. Their files are copied intact. A complete version-matched notice/source inventory for every embedded or transitive native component has **not** been established by this audit; the included ONNX notice collection alone is not evidence of exhaustive coverage. Before public redistribution, complete that inventory and any required corresponding-source delivery for the native build being distributed. This document does not claim that the native npm package folders contain upstream license files.

Version 0.16.0 pins the official MAA v6.19.0-beta.2 runtime, including its Arknights task resources, under resources/app/dist/resources/maa-v6.19.0-beta.2. This is MaaCore (AGPL-3.0), distinct from MaaFramework. Its pinned archive source and digest are recorded in gamepilot-provenance.json and games/arknights/engine-contract.json. The C# bridge calls its public C ABI in a separate process; process separation is not asserted to exempt license obligations. GamePilot does not reuse the WPF UI source. Device ADB software is supplied by the user's emulator or Android platform-tools installation; it is not bundled with the portable app.

MAA upstream source and build material: [v6.19.0-beta.2 source](https://github.com/MaaAssistantArknights/MaaAssistantArknights/tree/v6.19.0-beta.2). This local development distribution does not claim to provide an exhaustive corresponding-source bundle for upstream native dependencies. Official runtime notices are retained with the runtime. The self-contained bridge also carries the .NET runtime license and third-party notices.

## Distribution audit and public gate

`distribution-audit.json` inventories packaged native files, components, notice digests and corresponding-source artifacts. Default packages have scope `private-development` and explicitly set `legalComplianceClaimed: false`. Public packaging requires an explicit reviewed manifest; missing native components, license texts, pinned source digests or build materials block that mode. Remote links alone do not substitute for required accompanying source material. This engineering gate does not assert legal certification. Electron/Chromium notices and DSH's complete production dependency inventory remain included; unresolved LGPL/MPL/native source obligations remain visible as gaps.
