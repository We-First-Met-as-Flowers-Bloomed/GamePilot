新计划的执行授权来自本机结构化确认，绑定精确计划摘要与范围。模型读取、自然语言肯定句或正则不授予权限；否定语句只收窄范围。已有保存策略及原目标续跑保留原范围，不扩大权限。

临时 Copilot 准备只进行缓存、关卡和文件校验。本机确认后仍通过原协调器持有租约、写入冻结快照、调用原 worker，并使用原停止和账本通道。最终证据包含逐作业三星、执行前后 UID/主页及关联时序；任务链完成或日志含胜利文字不足以判定成功。已完成原生识别输出独立有界展示，不作为未知练度的替代证明。

方舟退出新增独立 ADB 进程观测，记录实例来源、设备、时间与两帧明确缺失。七天基线冻结配置并核对定时来源、身份、退出和逐项效果；遗失证据保持未完成。阴阳师预期角色可配置、冻结及只读双帧检查，但锚点未认证，自动恢复仍关闭；通用 MuMu 崩溃恢复尚未完成。

聊天轨迹、命令卡与故障状态优先使用订阅，保留 30 秒只读恢复；会话切换与卸载拒绝过期异步返回。可信游戏注册表支持契约排序及第三插件夹具，真实账号配置仅包含已适配游戏。安装、模板和引擎静态审计不能替代实机认证；公开分发缺对应源码或 notice 材料时阻止。

## 技术与边界

Electron + React + TypeScript；独立 Node worker 通过官方 @maaxyz/maa-node 调用 MaaFramework C++ 引擎。首版不引入 Python/Rust，不修改参考工程。

平台任务计划属于平台协议，包含 gameId、skillId、参数和步骤；不暴露 Maa Pipeline 作为平台公共 API。游戏包声明技能与就绪状态，执行适配器拥有引擎细节。设备控制与游戏业务分开。AI 只生成允许技能的结构化计划，计划经过运行时校验，不执行模型生成的 shell。

进程：renderer → preload 白名单 IPC → Electron main → utilityProcess worker → MaaFramework。renderer 无 Node 权限；主进程不加载 Maa 原生模块。请求具有 ID，超时后终止 worker；worker 退出拒绝所有未完成请求。设备动作串行；停止为独立控制消息，取消确认前不显示已取消。首阶段单设备，后续按设备分配 worker。

## 目录规则

Agent provider 只产生公开回复、工具意图和诊断；main 校验版本、账号、游戏日和宿主计划后向唯一协调器申请设备租约，worker 执行动作。game descriptors、编译器和内置 skill 同源。语义 journal 先落盘后订阅，分页冻结 seq 截面，旧事件重放仅作数据。CLI/MCP 经当前 profile 的本机 pipe 调用同一组 main 服务，不创建第二个执行器。

保存日常与自定义 Agent 子集共用执行入口，但完成语义分别处理：保存日常保留原设备 scope 和明确 primary/secondary slot，写原观察/日程完成记录；自定义子集和部分续跑不升级为整套日常。受理前同步登记可取消 controller，停止先向设备发出消息再等诊断或文件写入，避免受理或账本延迟吞掉停止。

```
gamepilot/
  apps/desktop/       # main、preload、renderer
  packages/protocol/  # 公共类型与运行时校验
  packages/runtime/   # 引擎适配、worker、运行状态
  games/onmyoji/      # 阴阳师技能清单、资源与说明
  tests/             # 协议、运行器、集成测试
  scripts/           # 构建与开发入口
  docs/              # 架构、计划、进度
  dist/              # 构建生成，git 忽略
```

App 保持根 package.json 和 package-lock.json；固定 DSH 底座在 `integrations/deepseek-harness/runtime` 使用独立锁文件及 Node 24.21.0，不向 App 的共享 node_modules 安装底座依赖。正式包包含独立 runtime、许可证和哈希清单，不包含会话、凭据或构建缓存。应用数据存 Electron userData，测试证据放 artifacts（忽略），禁止写入源码目录。参考文件位于项目外。

## 分阶段目标

M1 平台基础：可启动桌面应用；游戏技能目录；结构化计划验证；独立 worker；Maa 引擎版本与设备发现、连接截图；配置持久化；可停止的显式演练；错误日志与测试。

M2 阴阳师适配：从真实 MuMu 客户端采集资源，启动/登录态检查、签到；识别声望与当前挑战记录，执行地域鬼王并验证完成。没有截图和客户端验证的技能保持待适配，不能伪造坐标。

M3 AI：可配置模型服务生成平台计划，逐步加入截图观察、自定义流程草稿、试运行和版本化保存。未配置服务时不可把规则匹配描述为 AI。

M4 扩展：第二个游戏验证接口，之后再做多设备调度、定时执行和第三方插件。首版仅内置可信技能包，不开放任意代码插件。

## 阴阳师约束

上号默认复用用户已有登录态；首版预设阵容稳定完成日常。声望 2000/10000 的历史阈值必须通过当前游戏额度核验，不能单凭旧攻略决定点击次数。成功条件以游戏结果和完成记录为准。断线恢复先观察现状；不重复执行可能已完成的动作。

## 验收

平台测试覆盖未知技能、额外参数、状态切换、取消、并发拒绝、worker 故障和配置恢复。构建、TypeScript 检查、原生模块加载和桌面启动分别验证。硬件不可用时明确报告缺少真实设备验证，不以演练证明游戏自动化完成。
